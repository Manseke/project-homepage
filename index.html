01 / ABOUT

What is Hero Bunker?

A browser-based social deduction game where superheroes compete for limited bunker space during a global catastrophe.

🎭
01

Hidden Roles

Every player is assigned a unique combination of 5 secret traits — ability, weapon, race, weakness, and strength.

🌋
02

Threat Scenario

A random global catastrophe is revealed at the start — from Godzilla to a living black hole. Traits must counter the threat.

💬
03

Strategic Debate

Players reveal one trait per round, then debate and vote on who is least valuable to the bunker's survival.

🏆
04

Survival

The last half standing gain access to the bunker. One phone, no app install required — runs in any browser.

WHY THIS PROJECT EXISTS

Most party games require expensive equipment, physical cards, or dedicated hardware. Hero Bunker was created to be completely free, installable in zero steps, and playable anywhere with a single phone. The superhero theme keeps it engaging while the deduction mechanics encourage critical thinking, communication, and strategic decision-making — skills that go far beyond entertainment.

02 / GAMEPLAY

How the Game Works

Six phases, one phone, unlimited strategy. No two games are ever the same.

01

Player Setup

Choose how many players (4–8). Each player receives 5 secret traits — one from each category — fully randomised.

02

Threat Revealed

A dramatic threat screen displays the global crisis, which traits counter it, and the survival strategy players must consider.

03

Private Card View

Phone is passed to each player in turn. Only they see all 5 of their traits privately. They choose one to reveal publicly.

04

Group Discussion

Once all players have revealed one trait, the board shows all revealed cards. Players argue who deserves to survive.

05

Elimination Vote

The group votes to eliminate one player. Their card is stamped ELIMINATED and removed from future rounds.

06

Bunker Sealed

When survivors drop to half the original count, the bunker is sealed. Remaining players win. New round restarts fresh.

03 / REQUIREMENTS

Technical & Functional Requirements

What the product must do and how it was built to do it.

Functional Requirements

  • 4–8 players can join a session on a single device
  • System randomly assigns 5 independent traits per player
  • Pass-phone mechanic ensures private card viewing
  • Hidden traits are revealed one per player per round
  • Players discuss and vote to eliminate one per round
  • Game tracks elimination order and ends when half remain
  • A random threat scenario is displayed with counter-strategies
  • Language can be switched between Russian and English

Technical Requirements

  • Single HTML file — no install, no server, no accounts
  • Canvas API for 60fps animated city background
  • Web Audio API for procedural music and sound effects
  • CSS custom properties for consistent theming
  • Fully responsive — works on any smartphone
  • JavaScript ES6+ with index-based trait system
  • i18n object for bilingual UI (RU / EN)
  • GitHub repository and GitHub Pages hosting

Key Code — Player Setup

When the game starts, each player gets one random index per trait category. Indices are stored — not text strings — so language can switch without breaking saved state.

hero-bunker.js · startGame() JAVASCRIPT 
function startGame() {
  AUDIO.unlock();  AUDIO.click();
  const count = window._n;  // player count chosen on setup screen
  players = [];

  for (let i = 0; i < count; i++) {
    const traits = {}, rev = {};

    // Pick one RANDOM INDEX from each of the 5 categories
    CATS.forEach(c => {
      traits[c] = ri(DATA.pools.ru[c].length);  // random index, not text
      rev[c]    = false;                          // all hidden at start
    });

    players.push({
      name: lang === 'en' ? `Player ${i+1}` : `Игрок ${i+1}`,
      traits,                // { ABILITY: 7, WEAPON: 12, RACE: 3, … }
      revealed: rev,         // { ABILITY: false, WEAPON: false, … }
      revealedThisRound: false,
      eliminated: false,
    });
  }

  threatIdx = ri(DATA.threats.ru.length);  // pick random threat
  round = 1;  turnIdx = 0;
  showThreat();  // → dramatic full-screen threat reveal
}

Key Code — Animated Background

Buildings are pre-generated once with all random values stored. The draw loop reads stored data — no random calls during rendering, preventing flicker.

hero-bunker.js · Canvas City Background JAVASCRIPT 
// Generate buildings ONCE — store all randomness upfront
function genRow(minYf, maxYf, minW, maxW, alpha) {
  let x = -30;
  while (x < W + 100) {
    const w   = minW + ri(maxW - minW);
    const h   = H * (minYf + rnd() * (maxYf - minYf));
    const dmg = rnd() < .38;  // 38% of buildings are damaged

    // Pre-build jagged top — stored, not computed each frame
    const jag = [];
    if (dmg) {
      const steps = Math.ceil(w / 9) + 1;
      for (let i = 0; i <= steps; i++)
        jag.push({ x: x + (i/steps)*w, y: y + (rnd()<.4 ? rnd()*28 : rnd()*6) });
    }

    bldgs.push({ x, y: H-h, w, h, alpha, dmg, jag, wins: genWindows(…) });
    x += w + ri(14) - 4;
  }
}

// Draw loop — only reads pre-built data, no new Math.random() calls
function loop() {
  update();  // move particles, heroes, advance time
  draw();   // render sky → back bldgs → fire → front bldgs → heroes → UI
  requestAnimationFrame(loop);
}

Key Code — Procedural Audio

All audio is synthesized in the browser using Web Audio API oscillators. No audio files are downloaded — the entire soundtrack is generated from math.

hero-bunker.js · Web Audio — Elimination Sound JAVASCRIPT 
// Elimination: low boom + descending screech — entirely synthesized
eliminate() {
  if (!AC || !sfxOn) return;

  // Low bass boom (85Hz sawtooth, 0.9 seconds)
  const boom = AC.createOscillator(), bg = AC.createGain();
  boom.connect(bg); bg.connect(sfxGain);
  boom.type = 'sawtooth';  boom.frequency.value = 85;
  bg.gain.setValueAtTime(.45, AC.currentTime);
  bg.gain.exponentialRampToValueAtTime(.001, AC.currentTime + .9);
  boom.start(); boom.stop(AC.currentTime + .9);

  // Descending screech (640Hz → 90Hz over 0.6 seconds)
  const sc = AC.createOscillator(), sg = AC.createGain();
  sc.connect(sg); sg.connect(sfxGain);
  sc.type = 'sawtooth';
  sc.frequency.setValueAtTime(640, AC.currentTime + .08);
  sc.frequency.exponentialRampToValueAtTime(90, AC.currentTime + .7);
  sg.gain.setValueAtTime(0,   AC.currentTime);
  sg.gain.linearRampToValueAtTime(.28, AC.currentTime + .08);
  sg.gain.exponentialRampToValueAtTime(.001, AC.currentTime + .7);
  sc.start(); sc.stop(AC.currentTime + .7);
}
04 — FINAL REFLECTION
QUESTION 1

What improved the most from Alpha to Final?

The biggest leap was privacy and depth combined. In Alpha, there was no point debating because everyone could already see everyone's traits. The pass-phone mechanic changed the entire social dynamic — suddenly people actually had secrets to protect and arguments to make. Adding 5 independent trait categories instead of 3 class-linked ones gave players far more material to debate. No two characters are alike, which means every game conversation is different.

QUESTION 2

What feedback was most useful?

The most impactful feedback came from User Tester 2, who said "the background is just black." That single comment led to the entire Canvas API city animation — the most technically complex part of the project. It forced research into the Canvas API, particle systems, and procedural drawing. The sponsor's Alpha feedback about needing a "threat to react to" was also critical — it shaped the entire threat system which became the heart of the game's strategy.

QUESTION 3

What would you still improve?

The biggest missing feature is online multiplayer — right now everyone must share one device physically, which limits where you can play. A WebSocket-based system would let players use their own phones simultaneously. Beyond that: a custom trait editor so groups can add their own powers, a scoring system that tracks wins across sessions, and more threat scenarios. The visual background could also show the specific threat rather than a generic city.
